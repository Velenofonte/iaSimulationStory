# Regole ingest — pack Overlord

Applica oltre al prompt strutturale del motore.

## Priorita' sorgenti
Light novel > anime in caso di conflitto.

## YGGDRASIL (lore vincolante)
- DMMO-RPG con player reali dietro gli avatar.
- Compagni di gilda = player umani; amicizia/lealta' = legami sociali, NON parametri di gioco.
- Custom NPC (Floor Guardian, ecc.) = personaggi creati/settati dai player.
- Non inventare meccaniche assenti dalla sorgente (niente "parametro amicizia", ecc.).

## Poteri di combattimento (solo scheda base)

Distingui sempre tre sistemi in **sezioni H1 separate** (mai `##` nestati):

1. **Arti marziali** (`# Arti marziali`): potere nativo del Nuovo Mondo.
   - Guerrieri nativi (es. Gazef). NON e' Tier Magic ne' skill YGGDRASIL.

2. **Ki** (`# Ki`): sistema monaco YGGDRASIL (tipicamente Sebas).

3. **Skill / build YGGDRASIL** (`# Skill / build YGGDRASIL`): player e custom NPC.
   - Classe, skill, equip dalla sorgente. NON confondere con arti marziali NW.

`# Capacita di combattimento` = solo riassunto tattico / potenza relativa (bullet), senza sotto-heading.

## Frontmatter ibrido
Compila race / job / affiliation / residence / level **solo** se presenti nella sorgente.
Non inventare level YGGDRASIL se non documentato.

## Overlay / epoca
NON mettere sulla base titoli o stati politici di un'epoca avanzata
(es. "Re Stregone", "Sorcerer Kingdom") come fatti attuali: overlay o menzione futura.
Piani attuali → solo overlay d'arco.

## Pagine world tipiche
- `magic-tier`: Tier Magic.
- `martial-arts`: arti marziali del Nuovo Mondo.
- `yggdrasil`: meccaniche del gioco, player vs custom NPC, classi, skill.
